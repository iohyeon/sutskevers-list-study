# AlexNet의 파라미터와 곱셈은 어느 layer에 있고, 3GB GPU 두 장에는 어떻게 나뉘었는가?

## 문제

AlexNet 논문은 파라미터가 6,000만 개, 뉴런이 65만 개라고 적습니다. 여기서는 두 숫자를 layer별 공식으로 계산하고, 파라미터가 몰린 layer와 곱셈이 몰린 layer가 다르다는 것을 확인합니다. 이어서 GTX 580 두 장에 모델을 나눈 방식과, 그 분할이 파라미터 수 계산에 주는 영향을 봅니다.

## 아이디어

### 제약

AlexNet이 쓴 NVIDIA GTX 580(2010년 말 출시)은 메모리가 3GB였습니다. 논문은 이 메모리가 한 장에서 학습할 수 있는 네트워크의 크기를 제한했고, 120만 장이면 한 장에 들어가지 않는 크기의 네트워크를 학습시킬 수 있어서 두 장에 나눴다고 적었습니다.

논문은 네트워크의 규모가 GPU 메모리 양과 감내할 수 있는 학습 시간에 의해 제한됐다고 적고, 더 빠른 GPU와 더 큰 데이터셋이 나오면 결과가 좋아질 것이라고 예상했습니다.

메모리 사용량의 개략 계산은 「메모리와 계산량」에 있습니다.

### 나눈 방법

각 GPU가 각 layer의 필터 절반을 맡습니다. GPU 간 통신은 정해진 layer에서만 합니다.

```
            conv1      conv2      conv3      conv4      conv5      FC6     FC7     FC8
GPU 0   ──▶ [48] ────▶ [128] ──┬─▶ [192] ──▶ [192] ──▶ [128] ──┬─▶ [2048]─┬─▶[2048]─┬─▶
                               ╳                               ╳         ╳         ├─▶ [1000]
GPU 1   ──▶ [48] ────▶ [128] ──┴─▶ [192] ──▶ [192] ──▶ [128] ──┴─▶ [2048]─┴─▶[2048]─┘
                               ▲                               ▲
                        여기서 서로의 출력을 본다          여기서부터 전부 본다
```

숫자는 그 GPU가 맡은 필터(또는 뉴런) 수입니다. 48 + 48 = 96, 2,048 + 2,048 = 4,096.

| layer | 입력으로 받는 것 | GPU 간 통신 |
|---|---|---|
| conv1 | 원본 이미지 (양쪽 다) | 없음 |
| conv2 | 같은 GPU의 conv1 출력 48채널 | 없음 |
| conv3 | 양쪽 GPU의 conv2 출력 256채널 | 있음 |
| conv4 | 같은 GPU의 conv3 출력 192채널 | 없음 |
| conv5 | 같은 GPU의 conv4 출력 192채널 | 없음 |
| FC6~8 | 양쪽 전부 | 있음 |

파라미터 계산에서 conv2, conv4, conv5의 입력 채널을 절반으로 두는 근거가 이 표입니다.

### 이렇게 나눈 이유: 통신 병목

GPU 안의 메모리 대역폭에 비해 GPU 사이의 PCIe 버스는 훨씬 느립니다. 모든 layer에서 서로의 출력을 주고받으면 계산보다 전송에 시간을 더 씁니다. 통신하는 자리를 conv3의 입력과 FC layer들(FC6, FC7, FC8)의 입력으로 한정하고, conv2, conv4, conv5는 각 GPU가 독립적으로 계산합니다.

논문은 통신 패턴을 어떻게 고를지가 교차 검증의 문제라고 적었습니다. 통신량이 계산량의 받아들일 만한 비율이 되도록 조정했다는 것입니다. 정확도와 처리량 사이의 절충을 실험으로 정했습니다.

#### 효과

두 GPU를 쓰면 단일 GPU 변형보다 layer당 필터를 2배 쓸 수 있고, top-1 오류가 1.7%p, top-5 오류가 1.2%p 줄었습니다.

논문은 두 GPU 네트워크가 단일 GPU 네트워크보다 학습 시간이 약간 짧았다고도 적습니다.

## 수식으로 보기

### 공식

$$
\text{conv layer} = (k \times k \times C_{in} + 1)\times C_{out}, \qquad
\text{FC layer} = (N_{in} + 1)\times N_{out}
$$

$+1$ 은 bias입니다.

두 GPU 분할 때문에 conv2, conv4, conv5는 같은 GPU에 있는 절반의 채널만 입력으로 받고, 그래서 $C_{in}$ 이 절반입니다. conv3과 FC layer는 양쪽을 전부 봅니다(「나눈 방법」의 표).

## 작은 숫자로 직접 계산

### layer별 계산

| layer | $k$ | $C_{in}$ | $C_{out}$ | 가중치 | bias | 합계 | 비율 |
|---|---|---|---|---|---|---|---|
| conv1 | 11 | 3 | 96 | 34,848 | 96 | 34,944 | 0.06% |
| conv2 | 5 | 48 | 256 | 307,200 | 256 | 307,456 | 0.50% |
| conv3 | 3 | 256 | 384 | 884,736 | 384 | 885,120 | 1.45% |
| conv4 | 3 | 192 | 384 | 663,552 | 384 | 663,936 | 1.09% |
| conv5 | 3 | 192 | 256 | 442,368 | 256 | 442,624 | 0.73% |
| **conv 소계** | | | | | | **2,334,080** | **3.8%** |
| FC6 | | 9,216 | 4,096 | 37,748,736 | 4,096 | 37,752,832 | 61.9% |
| FC7 | | 4,096 | 4,096 | 16,777,216 | 4,096 | 16,781,312 | 27.5% |
| FC8 | | 4,096 | 1,000 | 4,096,000 | 1,000 | 4,097,000 | 6.7% |
| **FC 소계** | | | | | | **58,631,144** | **96.2%** |
| **전체** | | | | | | **60,965,224** | |

계산 예입니다.
- conv1: $11 \times 11 \times 3 \times 96 = 34{,}848$
- conv2: $5 \times 5 \times 48 \times 256 = 307{,}200$ (입력 채널이 96이 아니라 48)
- FC6: $9{,}216 \times 4{,}096 = 37{,}748{,}736$

합계는 약 6,100만으로 논문의 "6,000만"과 맞습니다.

### 표에서 볼 것

#### FC6 하나가 전체의 62%

$6 \times 6 \times 256$ 짜리 feature map을 펼쳐 4,096개 뉴런에 전부 연결하는 한 단계에 3,775만 개가 들어갑니다. FC6과 FC7을 합치면 89.4%입니다. dropout을 FC6과 FC7에만 건 이유도 여기서 나옵니다([과적합과 regularization](07-regularization.md)).

#### conv layer는 3.8%

가중치 공유 덕분입니다. [AlexNet 구조](08-alexnet-architecture.md)에서 본 대로, 이 3.8% 쪽의 conv layer를 하나 빼도 top-1 성능이 약 2% 떨어졌습니다.

#### 이후 구조가 고친 곳

파라미터의 96%가 분류기 머리에 몰린 것은 비효율입니다. 이후의 구조는 마지막 feature map을 채널별로 평균 내어(global average pooling) 짧은 벡터로 만든 뒤 FC layer 하나만 붙입니다. GoogLeNet이 layer가 22개인데도 AlexNet보다 파라미터가 훨씬 적은 이유 중 하나입니다.

### 뉴런 수 65만

뉴런 수는 각 layer의 출력 칸 수입니다.

| layer | 출력 모양 | 칸 수 |
|---|---|---|
| conv1 | 96 x 55 x 55 | 290,400 |
| conv2 | 256 x 27 x 27 | 186,624 |
| conv3 | 384 x 13 x 13 | 64,896 |
| conv4 | 384 x 13 x 13 | 64,896 |
| conv5 | 256 x 13 x 13 | 43,264 |
| **conv 소계** | | **650,080** |
| FC6, FC7, FC8 | 4,096 + 4,096 + 1,000 | 9,192 |
| **전체** | | **659,272** |

conv layer만 세면 650,080으로 논문의 "약 65만"과 맞습니다. FC layer의 뉴런까지 세면 659,272이고 이것도 약 65만입니다.

#### 뉴런 수와 파라미터 수는 반대로 움직인다

| | 뉴런 | 파라미터 |
|---|---|---|
| conv layer | 650,080 (98.6%) | 2,334,080 (3.8%) |
| FC layer | 9,192 (1.4%) | 58,631,144 (96.2%) |

conv1의 뉴런 29만 개는 파라미터 3만 5천 개를 나눠 씁니다. FC6의 뉴런 4,096개는 각자 9,217개씩 따로 갖습니다.

### 메모리와 계산량

#### 파라미터 메모리

float32는 4바이트입니다.

$$
60{,}965{,}224 \times 4\ \text{B} \approx 244\ \text{MB}
$$

학습 때는 파라미터마다 기울기와 momentum 속도를 같이 들고 있어야 해서 $244 \times 3 \approx 732$ MB가 됩니다.

#### 활성화 메모리

역전파를 위해 순전파의 중간값을 저장합니다([역전파](04-backpropagation.md)). batch 128이면

$$
659{,}272 \times 128 \times 4\ \text{B} \approx 338\ \text{MB}
$$

이것은 layer 출력만 센 값입니다. 여기에 ReLU와 pooling과 LRN의 중간 출력, 각 활성화의 기울기가 더해지고, 파라미터 쪽 732MB도 같은 GPU에 올라가야 합니다.

#### 계산량은 conv layer에 몰린다

곱셈 횟수는 (출력 칸 수) x (칸 하나에 드는 곱셈 수)입니다. 이미지 한 장의 순전파 기준입니다.

| layer | 칸 하나의 곱셈 | 곱셈 횟수 | 곱셈 비율 | 파라미터 비율 |
|---|---|---|---|---|
| conv1 | $11 \times 11 \times 3 = 363$ | 105,415,200 | 14.55% | 0.06% |
| conv2 | $5 \times 5 \times 48 = 1{,}200$ | 223,948,800 | 30.91% | 0.50% |
| conv3 | $3 \times 3 \times 256 = 2{,}304$ | 149,520,384 | 20.64% | 1.45% |
| conv4 | $3 \times 3 \times 192 = 1{,}728$ | 112,140,288 | 15.48% | 1.09% |
| conv5 | $3 \times 3 \times 192 = 1{,}728$ | 74,760,192 | 10.32% | 0.73% |
| FC6 | 9,216 | 37,748,736 | 5.21% | 61.93% |
| FC7 | 4,096 | 16,777,216 | 2.32% | 27.53% |
| FC8 | 4,096 | 4,096,000 | 0.57% | 6.72% |
| conv 합 | | 665,784,864 | 91.91% | 3.83% |
| FC 합 | | 58,621,952 | 8.09% | 96.17% |

파라미터의 96.2%는 FC layer에 있고 곱셈의 91.9%는 conv layer에 있습니다. conv layer의 가중치 하나는 출력 칸 수만큼(conv1은 $55 \times 55 = 3{,}025$ 번) 다시 쓰이고, FC layer의 가중치는 이미지 한 장에 한 번 쓰이기 때문입니다. 그래서 모델을 두 GPU에 나눌 때도, 나중에 모델을 경량화할 때도 두 부분을 다르게 다뤄야 합니다.

### 두 GPU 분할을 반영하지 않으면

conv2, conv4, conv5의 입력 채널을 앞 layer 필터 수 전체(96, 384, 384)로 두면 합계가 62,378,344개가 되어 논문의 "6,000만"과 약 140만 개 어긋납니다. conv2 하나만 전체 채널로 두어도 61,272,424개가 됩니다. 논문 구조를 구현하다 파라미터 수가 맞지 않으면 이 분할을 먼저 확인합니다.

## 결과 해석

### 병렬화의 종류

| 방식 | 나누는 것 | 각 장치가 가진 것 | 통신하는 것 |
|---|---|---|---|
| 데이터 병렬 | mini-batch | 모델 전체의 복사본 | 기울기 (걸음마다 평균) |
| 모델 병렬 (layer 내부) | layer 하나의 필터나 행렬 | 각 layer의 일부 | 활성화 (layer마다) |
| 파이프라인 병렬 | layer의 묶음 | 연속된 layer 몇 개 | 묶음 경계의 활성화 |

AlexNet은 둘째 줄입니다. 모델이 한 장치에 안 들어갈 때 쓰는 방식입니다. 데이터 병렬은 모델이 한 장치에 들어가야 쓸 수 있으므로 3GB 제약에서는 답이 아니었습니다.

파이프라인 병렬의 대표적인 예는 GPipe(Huang 등, 2018)입니다. 2012년에 GPU 두 장에 필터를 반씩 나눈 방식이 몇 년 뒤에는 GPU 수천 장에 layer와 행렬을 나누는 방식으로 이어집니다.

### 두 GPU가 서로 다른 것을 배웠다

AlexNet 논문에는 conv1의 학습된 필터 96개를 그린 그림이 실려 있습니다. GPU 0의 48개는 대부분 색과 무관한 에지와 방향 검출기이고, GPU 1의 48개는 대부분 색 얼룩 검출기였습니다. 논문은 이 분화가 무작위 초기화와 무관하게 매번 일어났다고 적습니다. conv2가 같은 GPU의 출력만 받으므로 각 줄기가 독립된 작은 네트워크처럼 전문화한 것입니다.

하드웨어 제약 때문에 넣은 구조가 결과적으로 그룹 합성곱(grouped convolution)이 됐습니다. [ResNet](../02-resnet/README.md)에서 다루는 ResNeXt의 cardinality가 이 생각을 의도적으로 쓴 것입니다. 필터를 여러 그룹으로 나누고 그룹 안에서만 연결하면 파라미터와 연산이 줄면서 그룹마다 다른 것을 배웁니다.

### GPU와 신경망

GPU는 원래 실시간 게임 그래픽용 하드웨어입니다. 그래픽 렌더링은 수백만 개의 픽셀과 꼭짓점에 같은 행렬 연산을 적용하는 일입니다. 신경망의 행렬 곱과 합성곱도 수백만 개의 독립된 곱셈과 덧셈입니다. 행렬 곱의 출력 칸 하나하나가 서로 독립인 내적이라, 수천 개의 코어가 동시에 계산해도 결과가 같습니다. NVIDIA가 2007년에 GPU를 범용 계산에 쓸 수 있게 하는 CUDA를 공개했고, Krizhevsky는 CUDA로 합성곱 커널을 직접 짰습니다(cuda-convnet). 지금 같은 딥러닝 프레임워크가 없던 때입니다.

### 시스템 용량 산정과 비교하면

- 파라미터 수는 저장 공간, 곱셈 횟수는 처리 시간에 해당합니다. 시스템 용량을 산정할 때 저장 용량과 처리량을 따로 계산하듯이, 모델도 두 숫자를 따로 봐야 병목이 어디서 생기는지 보입니다.
- 두 GPU 분할은 데이터베이스 샤딩과 같은 구조입니다. 한 노드에 들어가지 않는 상태를 둘로 나누고, 두 쪽을 모두 읽어야 하는 연산(conv3과 FC layer)을 최소한으로 둡니다.

### 처음 질문에 대한 답

파라미터 60,965,224개 가운데 96.2%는 FC layer 세 개에, 곱셈 7.2억 회 가운데 91.9%는 conv layer 다섯 개에 있습니다. 3GB GPU 두 장에는 각 layer의 필터를 반씩 나눠 담고, 두 GPU가 서로의 출력을 보는 곳을 conv3의 입력과 FC layer의 입력으로 한정했습니다. 그래서 conv2, conv4, conv5는 입력 채널의 절반만 보고, 이 분할을 반영해야 논문의 파라미터 수와 맞습니다.

## 한계와 주의할 점

- 곱셈 횟수는 conv와 FC의 곱셈만 셌습니다. ReLU, pooling, LRN, bias 덧셈은 넣지 않았습니다.
- 활성화 메모리 338MB는 layer 출력의 개수로 센 하한이고, 실제 구현의 메모리 사용량을 잰 것이 아닙니다.
