# 프레임별 확률에서 문장을 어떻게 고르는가?

## 문제

CTC로 학습한 모델이 내놓는 것은 문장이 아니라 행렬입니다. 프레임 $T$ 개마다 기호 $K$ 개의 확률이 있습니다. 여기서 문장 하나를 골라야 합니다.

[CTC 학습](05-ctc-alignment.md)에서 라벨의 확률은 그 라벨로 접히는 경로 전체의 합이었습니다.

$$
P(y|x) = \sum_{\pi \in \mathcal{B}^{-1}(y)} \prod_{t=1}^{T} p_t(\pi_t)
$$

디코딩은 이 값을 가장 크게 하는 $y$ 를 찾는 것입니다.

$$
\hat{y} = \arg\max_{y} P(y|x)
$$

이 최댓값을 정확히 구하는 방법은 알려져 있지 않습니다. 학습 때는 정답 $y$ 가 하나로 정해져 있어서 표 하나를 채우면 됐지만, 디코딩에서는 $y$ 자체가 미지수이고 후보가 $K^T$ 개의 경로에서 접히는 모든 문자열입니다. 그래서 두 가지 근사를 씁니다.

1. 경로 하나만 봅니다. 프레임마다 확률이 가장 높은 기호를 골라 접습니다. greedy 디코딩, 또는 best path 디코딩입니다.
2. 접두사 단위로 후보를 몇 개씩 들고 갑니다. 문자열 접두사마다 그 접두사로 이어지는 경로들의 확률 합을 유지하면서 폭 $W$ 개만 살립니다. prefix beam search입니다.

여기에 CTC의 가정 하나가 더 얽힙니다. CTC는 프레임끼리 조건부 독립을 가정하므로 출력 분포에 글자 사이의 제약이 들어 있지 않습니다. 디코딩 단계에서 외부 언어 모델을 붙이는 이유입니다. Deep Speech 2(Amodei 외, 2015)의 디코딩이 언어 모델을 결합한 beam search이고, beam 폭은 영어 500, 중국어 200입니다.

이 문서에서는 두 방법을 직접 구현해 합성 확률 행렬에서 비교하고, 언어 모델 가중치 $\alpha$ 와 길이 보정 $\beta$ 의 효과를 재고, greedy가 지는 경우를 실측으로 보입니다.

## 아이디어

### greedy 디코딩은 무엇을 근사하나

greedy 디코딩은 가장 확률이 높은 경로 하나를 찾아서 접습니다.

$$
\hat{\pi} = \arg\max_{\pi} P(\pi|x) = \big( \arg\max_k p_1(k), \dots, \arg\max_k p_T(k) \big), \qquad \hat{y} = \mathcal{B}(\hat{\pi})
$$

프레임끼리 독립이므로 최적 경로는 프레임별 argmax를 이어 붙인 것입니다. 계산은 $O(TK)$ 이고 구현은 몇 줄입니다.

문제는 $\arg\max_\pi P(\pi|x)$ 와 $\arg\max_y P(y|x)$ 가 다른 것을 찾는다는 데 있습니다. 라벨의 확률은 경로 묶음의 합인데 greedy는 묶음의 크기를 보지 않습니다. 확률이 조금 낮은 경로가 여러 개 모여 있으면 합이 더 클 수 있습니다.

### prefix beam search가 유지하는 것

경로가 아니라 문자열을 후보로 둡니다. 프레임을 하나씩 읽으면서 각 후보 문자열 $\ell$ 에 대해 두 값을 유지합니다.

- $p_b(\ell)$: 지금까지 읽은 프레임이 $\ell$ 로 접히고, 마지막 프레임이 blank인 경로들의 확률 합.
- $p_{nb}(\ell)$: 같은 조건에서 마지막 프레임이 blank가 아닌 경로들의 확률 합.

두 값을 나누는 이유는 다음 프레임의 처리가 달라지기 때문입니다. 다음 프레임에 $\ell$ 의 마지막 글자와 같은 글자가 오면, 마지막이 blank였다면 글자가 하나 늘고 blank가 아니었다면 같은 글자가 이어져 접힙니다. 이 구분 없이는 `tt` 와 `t` 를 가를 수 없습니다.

한 프레임을 읽을 때 각 후보를 기호마다 확장합니다.

| 읽은 기호 | 어디로 가나 | 어떻게 더하나 |
|---|---|---|
| blank | 같은 후보 $\ell$ | $p_b(\ell) \mathrel{+}= (p_b + p_{nb})(\ell) \cdot p_t(\text{blank})$ |
| $\ell$ 의 마지막 글자 $c$ | 같은 후보 $\ell$ | $p_{nb}(\ell) \mathrel{+}= p_{nb}(\ell) \cdot p_t(c)$ |
| $\ell$ 의 마지막 글자 $c$ | 늘어난 후보 $\ell c$ | $p_{nb}(\ell c) \mathrel{+}= p_b(\ell) \cdot p_t(c)$ |
| 그 외 글자 $c'$ | 늘어난 후보 $\ell c'$ | $p_{nb}(\ell c') \mathrel{+}= (p_b + p_{nb})(\ell) \cdot p_t(c')$ |

프레임을 다 읽으면 $p_b + p_{nb}$ 가 가장 큰 후보를 냅니다. 각 프레임에서 상위 $W$ 개만 남기는 것이 beam이고, $W$ 를 무한히 키우면 모든 문자열을 들고 가는 정확한 계산이 됩니다.

### 언어 모델과 길이 보정

CTC 점수만으로 고르면 문제가 둘 있습니다.

- 글자 사이의 제약이 없습니다. 음향 점수가 비슷하면 `signal` 과 `sygnal` 을 구분할 근거가 없습니다.
- 언어 모델 확률은 글자를 늘릴 때마다 1보다 작은 수를 곱하므로, 언어 모델을 붙이면 짧은 문장이 유리해집니다.

그래서 점수를 셋의 합으로 씁니다.

$$
Q(y) = \log P_{ctc}(y|x) + \alpha \log P_{lm}(y) + \beta |y|
$$

- $\alpha$: 언어 모델 가중치. 두 확률의 단위가 다르므로(음향 점수는 프레임마다 곱해지고 언어 모델 점수는 글자마다 곱해집니다) 그대로 더할 수 없습니다.
- $\beta$: 글자 하나당 상수 보상. $\alpha \log P_{lm}$ 이 주는 길이 벌점을 되돌립니다. Deep Speech 2가 쓰는 항과 같은 형태입니다.

구현에서는 후보를 글자 $c$ 로 늘릴 때 $\alpha \log P_{lm}(c \,|\, \ell) + \beta$ 를 더합니다. 문장이 끝난 뒤 한 번에 더하는 것과 같은 값이 되고, beam에서 후보를 자를 때 이미 반영되어 있습니다.

## 수식으로 보기

### 두 argmax의 차이를 만드는 최소 예

프레임 4개, 기호 두 종류만 생각합니다. 모든 프레임에서 $p_t(\text{blank}) = 0.36$, $p_t(c) = 0.32$ 라고 하면 argmax는 매 프레임 blank이므로 greedy는 빈 문자열을 냅니다.

두 라벨의 확률을 비교합니다. 빈 문자열이 되는 경로는 네 프레임 모두 blank인 하나입니다.

$$
P(\varepsilon | x) = 0.36^4 = 0.016796
$$

`c` 로 접히는 경로는 `blank`$^i$ `c`$^j$ `blank`$^k$ 꼴이고 $i + j + k = 4$, $j \ge 1$ 입니다. $j$ 별로 배치 수를 세면 4, 3, 2, 1개, 합쳐서 10개입니다.

$$
P(c|x) = \sum_{j=1}^{4} (5-j) \cdot 0.36^{\,4-j} \cdot 0.32^{\,j}
$$
$$
= 4 (0.36^3)(0.32) + 3 (0.36^2)(0.32^2) + 2 (0.36)(0.32^3) + 1 \cdot 0.32^4
$$
$$
= 0.059719 + 0.039813 + 0.023593 + 0.010486 = 0.133612
$$

경로 하나하나는 모두 $0.36^4$ 보다 작은데($0.36^3 \times 0.32 = 0.014930$) 합은 7.95배 큽니다. greedy는 경로를 하나만 보므로 이 비교를 할 수 없습니다.

### beam 폭이 늘 때 계산량

프레임 하나에서 각 후보를 기호마다 확장하므로 확장 후보 수는 다음 크기입니다.

$$
\text{확장 수} \approx T \cdot W \cdot K'
$$

$K'$ 는 그 프레임에서 확률이 임계값을 넘은 기호 수입니다. 전체 어휘 $K$ 를 다 보는 대신 확률이 낮은 기호를 미리 버리는 것을 프레임별 가지치기라고 합니다. 계산량은 $W$ 에 선형이고, 정확도는 $W$ 를 키워도 어느 지점부터 더 오르지 않습니다. 두 곡선이 만나는 자리가 beam 폭을 고르는 근거입니다.

## 코드로 확인

### 합성 확률 행렬

음성 데이터를 내려받지 않고 목표 문장을 프레임으로 늘립니다. 글자 하나를 3~5프레임으로 펴고, 글자 사이에 blank 프레임을 0~2개 넣습니다(같은 글자가 이어지는 자리에는 1개 이상). 그리고 두 가지 잡음을 심습니다.

- 약한 발음(글자의 30%): 정답 글자 0.32, blank 0.36. 프레임별 argmax가 blank가 되므로 greedy는 이 글자를 빠뜨립니다.
- 혼동 짝(글자의 30%): 경쟁 글자 0.50, 정답 글자 0.33. `a`/`e`, `b`/`d`, `l`/`r` 처럼 짝을 미리 정해 두었습니다. greedy와 음향 점수만 쓰는 beam search는 경쟁 글자를 고릅니다.

```python
if weak:
    p_true, p_blank = 0.32, 0.36
elif rival:
    p_true, p_blank = 0.33, 0.06        # 경쟁 글자에 0.50
else:
    p_true, p_blank = 0.80, 0.05
```

언어 모델은 같은 문법으로 만든 문장 4,000개(137,784글자)로 학습한 글자 6-gram입니다. 차수 1부터 6까지를 4의 거듭제곱 가중치로 섞고 add-0.1 스무딩을 씁니다. 시험 문장은 학습에 없는 문장입니다.

### prefix beam search

`experiments/ctc_decode.py` 의 본체입니다. 위 표의 네 줄이 그대로 들어 있습니다.

```python
for pref, (pb, pnb) in cur.items():
    ptot = lse(pb, pnb)                          # log(p_b + p_nb)
    last = pref[-1] if pref else None
    for k in cands:                              # 가지치기를 통과한 기호만
        if k == BLANK:
            e = nxt[pref]
            e[0] = lse(e[0], ptot + lg[k])       # p_b(같은 후보)
            continue
        ch = SYMS[k]
        if ch == last:
            e = nxt[pref]
            e[1] = lse(e[1], pnb + lg[k])        # p_nb(같은 후보), 글자가 이어짐
            ext = pb                             # 늘릴 때는 blank 뒤에서만
        else:
            ext = ptot
        bonus = alpha * lm.logp(pref, ch) + beta # 언어 모델과 길이 보정
        e2 = nxt[pref + ch]
        e2[1] = lse(e2[1], ext + lg[k] + bonus)
cur = dict(sorted(nxt.items(), key=lambda kv: -lse(kv[1][0], kv[1][1]))[:beam])
```

전부 로그 공간이고 덧셈은 `lse`(log-sum-exp)로 합니다. 프레임 수백 개를 지나면 확률이 float64의 범위를 벗어나기 때문입니다([CTC 학습](05-ctc-alignment.md)의 언더플로 측정).

정확도는 문자 오류율(CER)로 잽니다. 정답과 출력 사이의 편집 거리를 정답 글자 수로 나눈 값입니다.

## 실험 결과

시험 발화 16개, 목표 글자 555개, 프레임 2,796개(발화당 평균 174.8)입니다. 약한 발음이나 혼동을 심은 글자가 259개입니다([results/ctc-decode.txt](results/ctc-decode.txt)).

### greedy 디코딩

```
greedy CER = 46.31% (편집거리 257 / 글자 555), 완전히 맞은 발화 0/16
```

심어 둔 잡음 259개가 거의 그대로 오류가 됩니다. 약한 발음은 글자가 빠지고 혼동 짝은 글자가 바뀝니다.

### $\alpha$ 와 $\beta$ 고르기

시험 발화와 겹치지 않는 dev 발화 8개에서 beam 50으로 격자 탐색했습니다. 값은 CER입니다.

| $\alpha$ | $\beta = 0$ | $\beta = 0.5$ | $\beta = 1.0$ | $\beta = 2.0$ |
|---|---|---|---|---|
| 0.0 | 27.72% | 45.96% | 112.63% | 210.88% |
| 0.3 | 0.35% | 0.35% | 0.35% | 1.05% |
| 0.6 | 0.00% | 0.00% | 0.00% | 0.00% |
| 1.0 | 0.00% | 0.00% | 0.00% | 0.00% |
| 1.5 | 0.00% | 0.00% | 0.00% | 0.00% |

첫 줄이 $\beta$ 의 성격을 보여 줍니다. $\alpha = 0$ 이면 $\beta$ 는 글자를 늘리는 보상만 남기므로 CER이 27.72%에서 210.88%로 올라갑니다. CER이 100%를 넘는 것은 삽입 오류가 정답 글자 수보다 많아졌다는 뜻입니다. $\beta$ 는 $\alpha \log P_{lm}$ 이 주는 길이 벌점을 되돌리는 항이므로 $\alpha$ 없이 쓰면 방향만 남습니다.

$\alpha \ge 0.6$ 에서 dev CER이 0이 되어 $\beta$ 의 차이가 보이지 않습니다. 이 설정에서는 $\alpha = 0.6$, $\beta = 0$ 을 골랐습니다.

### beam 폭별 정확도와 계산량

시험 발화 16개입니다. "확장 수"는 (후보, 기호) 쌍을 몇 번 계산했는지이고, "접두사"는 프레임마다 살아남은 후보 수의 평균입니다.

| beam | CER (언어 모델 없음) | CER (언어 모델 결합) | 맞은 발화 (결합) | 확장 수 | 접두사 | 초 (결합) |
|---|---|---|---|---|---|---|
| 1 | 46.31% | 100.00% | 0/16 | 7,951 | 1.0 | 0.0 |
| 2 | 28.47% | 22.88% | 3/16 | 15,854 | 2.0 | 0.0 |
| 4 | 28.29% | 2.88% | 9/16 | 31,612 | 4.0 | 0.0 |
| 8 | 28.65% | 0.54% | 14/16 | 62,888 | 8.0 | 0.0 |
| 16 | 30.99% | 0.36% | 15/16 | 124,946 | 15.8 | 0.1 |
| 50 | 32.25% | 0.36% | 15/16 | 386,313 | 48.8 | 0.2 |
| 100 | 32.97% | 0.36% | 15/16 | 767,380 | 96.8 | 0.5 |
| 200 | 32.79% | 0.36% | 15/16 | 1,523,391 | 192.0 | 1.0 |
| 500 | 32.61% | 0.36% | 15/16 | 3,770,573 | 474.8 | 2.5 |

읽을 것이 네 가지입니다.

**언어 모델을 결합하면 beam 8에서 CER 46.31%가 0.54%로 내려갑니다.** beam 16부터 0.36%(글자 2개 오류, 15/16 발화 정답)에서 멈춥니다. 확장 수는 beam 1의 7.9배입니다.

**beam 폭을 16에서 500으로 31배 키워도 CER이 그대로입니다.** 확장 수는 3,770,573로 30배, 시간은 0.1초에서 2.5초로 늘어납니다. 후보 수 평균이 474.8이므로 beam이 비어서 멈춘 것이 아니고, 추가로 들고 간 후보가 답을 바꾸지 못한 것입니다.

**언어 모델 없이 beam 폭을 키우면 CER이 나빠집니다.** beam 2에서 28.47%였다가 beam 100에서 32.97%가 됩니다. beam search가 제대로 작동한 결과입니다. 폭이 넓어지면 $\log P_{ctc}$ 가 더 큰 문자열을 찾아내는데, 이 합성 설정에서 그런 문자열은 혼동 짝을 둘 다 넣은 형태입니다(아래 출력 예의 `iyielnlnow`). 음향 점수만으로는 그것이 틀린 문자열이라는 근거가 없습니다. 탐색을 잘하는 것과 답을 맞히는 것이 다른 문제라는 것을 보여 줍니다.

**beam 1에 언어 모델을 붙이면 CER이 100%가 됩니다.** 출력이 빈 문자열입니다.

```
목표 'this yellow mirror ran' -> 출력 ''
목표 'a cold river slept again near the signal' -> 출력 ''
```

$\alpha \log P_{lm} \le 0$ 이므로 글자를 늘리면 점수가 깎입니다. 후보를 하나만 들고 가면 아무 글자도 내지 않는 경로가 계속 1위를 차지하고, 그 뒤에 이어질 글자로 만회할 기회가 없습니다. 언어 모델과 beam 폭은 따로 고를 수 있는 값이 아닙니다.

### greedy가 지는 구체적인 경우

세 발화입니다. beam 500은 언어 모델을 붙이지 않은 결과입니다.

```
beam 500 + LM : this yellow mirror ran         (편집거리 0)
```

```
목표          : a cold river slept again near the signal
greedy        : cod lvrslp againner h sygna                     (편집거리 15)
beam 500      : ae cold lrliver slept again near tdhe syiygnal   (편집거리 6)
beam 500 + LM : a cold river slept again near the signal         (편집거리 0)
```

```

greedy        : a cond milur pea egaen                (편집거리 10)
beam 500      : a cond mirlrlur uopenaead eaegaeien   (편집거리 11)

```

두 종류의 실패가 보입니다.

- greedy는 글자를 빠뜨립니다. `this` 의 `t`, `river` 의 `i` 와 `e` 처럼 약한 발음으로 심어 둔 자리입니다. blank가 매 프레임 argmax이므로 경로 하나만 보면 이 글자가 없는 것이 맞습니다.
- 음향 점수만 쓰는 beam search는 글자를 덧붙입니다. `iyielnlnow`, `syiygnal`, `mirlrlur` 처럼 혼동 짝의 두 글자가 다 들어갑니다. 두 글자가 모두 확률을 받고 있으므로 둘 다 내는 경로 묶음의 합이 하나만 내는 쪽보다 큽니다.

언어 모델이 두 실패를 같이 잡습니다. `yellow` 뒤에 올 수 있는 글자와 `iyielnlnow` 같은 배열의 확률 차이가 크기 때문입니다.

### 언어 모델을 결합하고도 남은 오류

beam 50에서 남은 오류는 하나이고 글자 2개입니다.

```
목표 : this warm letter followed slowly
출력 : the warm letter followed slowly
```

두 문장의 점수를 항별로 계산했습니다($\alpha = 0.6$).

| 문장 | $\log P_{ctc}$ | $\alpha \log P_{lm}$ | 합 |
|---|---|---|---|
| `this warm letter followed slowly` | -60.221 | -16.033 | -76.255 |
| `the warm letter followed slowly` | -60.057 | -15.897 | -75.954 |

두 항 모두 `the` 쪽이 높습니다. 음향 점수에서 이미 0.164 앞서 있고 언어 모델에서 0.136 더 앞섭니다. `this` 의 `i` 를 약한 발음으로 심어 두었기 때문에 음향 점수가 `the` 를 선호하고, 말뭉치에서 `the` 가 `this` 보다 흔하기 때문에 언어 모델도 같은 쪽을 가리킵니다. beam 폭을 500으로 키워도 이 오류는 남습니다. 탐색 실패가 아니라 점수 함수가 이 문장에 잘못된 순위를 준 것이므로, 폭을 늘려서는 고칠 수 없습니다.

### 프레임별 가지치기

beam 50, 언어 모델 결합에서 임계값만 바꿨습니다.

| 임계값 | CER | 확장 수 | 초 |
|---|---|---|---|
| 0 (가지치기 없음) | 0.36% | 3,882,592 | 2.9 |
| $10^{-4}$ | 0.36% | 3,882,592 | 2.6 |
| $5 \times 10^{-3}$ | 0.36% | 386,313 | 0.2 |
| $5 \times 10^{-2}$ | 0.36% | 284,380 | 0.2 |

임계값 $5 \times 10^{-3}$ 에서 확장 수가 10분의 1로, 시간이 14분의 1로 줄고 CER은 그대로입니다. 이 합성 설정에서 확률이 그보다 낮은 기호는 정답 경로에 들어가지 않습니다. $10^{-4}$ 에서 효과가 없는 이유는 잡음을 나머지 확률을 26개 기호에 퍼뜨려 만들었기 때문이고, 기호 하나당 몫이 $10^{-4}$ 보다 큽니다.

## 결과 해석

greedy와 beam search의 차이는 구현 난이도가 아니라 무엇을 비교하는지에 있습니다. greedy는 경로 하나끼리 비교하고 beam search는 경로 묶음의 합끼리 비교합니다. 위 최소 예에서 경로 하나로는 blank만 쓴 쪽이 크지만($0.36^4 = 0.016796$) 묶음의 합으로는 `c` 를 내는 쪽이 7.95배 큽니다. CTC가 정의하는 목적 함수가 후자이므로 greedy는 목적 함수와 다른 것을 최적화합니다.

beam 폭은 두 가지를 한꺼번에 정합니다. 탐색의 완전성과 계산량입니다. 위 측정에서 확장 수는 폭에 정확히 선형이고(beam 500이 beam 1의 474.2배), 정확도는 폭 16에서 포화합니다. 폭을 더 키워서 나아지지 않는 오류는 점수 함수가 잘못 준 순위이므로 탐색으로 고칠 수 없습니다. Deep Speech 2가 영어 500, 중국어 200을 쓴 것도 이 성질에서 나옵니다. 폭은 언어와 출력 단위마다 따로 정해야 하는 값이고, 정확도가 포화하는 지점을 넘어서면 지연만 늘어납니다. 논문의 배포 시스템은 스트림 10개를 동시에 처리하면서 중앙값 지연 44ms, 98퍼센타일 지연 70ms를 지킵니다. beam 폭이 지연 예산에 직접 들어가는 값입니다.

언어 모델을 붙이는 이유도 측정에서 드러납니다. 언어 모델 없이 폭을 키우면 CER이 28.47%에서 32.97%로 나빠졌습니다. CTC 출력만으로는 글자 사이의 제약이 없으므로, 탐색을 잘하면 오히려 음향적으로만 그럴듯한 문자열을 찾아냅니다. CTC의 조건부 독립 가정이 학습에서는 계산을 가능하게 해 주고 디코딩에서는 비용으로 돌아옵니다. $\alpha$ 와 $\beta$ 는 그 비용을 되메우는 두 개의 손잡이입니다.

## 한계와 주의할 점

### 합성 확률 행렬이다

여기서 쓴 확률 행렬은 음성 모델의 출력이 아니라, 목표 문장에서 규칙으로 만든 것입니다. 잡음의 종류(약한 발음, 혼동 짝)와 세기(0.32/0.36, 0.50/0.33)를 사람이 정했으므로 오류의 분포가 실제 음성 인식과 같지 않습니다. 특히 greedy의 CER 46.31%는 잡음 비율을 정한 결과이고 실제 시스템의 값이 아닙니다.

비교 자체는 이 조건에서 유효합니다. 두 디코더가 같은 행렬을 받고 같은 정답으로 채점되기 때문입니다. 실제 음성에서 확인해야 하는 것은 오류의 비율이 아니라 순서, 즉 beam search가 greedy보다 낫고 언어 모델이 더 낫다는 순서입니다.

### 언어 모델이 시험 문장과 같은 문법에서 나왔다

학습 문장과 시험 문장이 같은 단어 목록과 같은 문법으로 만들어졌습니다. 시험 문장 자체는 학습에 없지만 단어와 단어 결합 패턴이 모두 학습에 있습니다. 실제 시스템의 언어 모델은 이보다 훨씬 불리한 조건에 놓입니다. 그래서 $\alpha = 0.6$ 에서 dev CER이 0으로 떨어진 것은 이 합성 조건의 성질이고, $\alpha$ 의 적정값으로 옮겨 쓸 수 없습니다. 격자 탐색에서 $\alpha \ge 0.6$ 의 값이 모두 0인 것도 같은 이유입니다.

### 글자 단위 언어 모델이다

Deep Speech 2는 단어 단위 n-gram을 씁니다. 여기서는 구현을 접두사 확장에 맞추기 위해 글자 6-gram을 썼습니다. 글자 단위는 후보를 글자 하나 늘릴 때마다 점수를 줄 수 있어 beam search와 붙이기 쉽지만, 단어 경계를 넘는 제약은 6글자 안쪽만 봅니다. 단어 단위 모델을 쓰면 단어가 끝나는 자리에서만 점수를 줄 수 있어 beam 안에서 점수 시점이 어긋나는 문제를 따로 다뤄야 합니다.

### 문장 끝을 처리하지 않았다

문장이 끝났다는 것에 언어 모델 점수를 주지 않았습니다. 실제 구현은 마지막에 문장 끝 기호의 확률을 한 번 더 곱해, 중간에 끊긴 후보가 유리해지지 않게 합니다. 여기서는 모든 후보가 같은 프레임 수를 소비하므로 이 항이 없어도 비교가 성립하지만, 문장 끝에서 잘린 출력을 걸러내지는 못합니다.

### 측정 조건

시험 발화 16개, seed 하나입니다. CER 0.36%는 글자 2개 차이이므로 seed를 바꾸면 이 자리의 값은 흔들립니다. 반면 greedy 46.31%와 언어 모델 결합 0.36%의 차이는 크기가 100배 이상이라 이 규모에서도 방향이 뒤집히지 않습니다. 시간은 다른 작업이 함께 돌던 상태에서 잰 값입니다.

## 확인 문제

1. greedy 디코딩이 찾는 것과 CTC가 정의하는 최적 라벨이 다른 이유는 무엇인가요? (답: greedy는 $\arg\max_\pi P(\pi|x)$ 를 찾고 CTC의 목표는 $\arg\max_y P(y|x)$ 입니다. 후자는 경로 묶음의 합입니다)
2. prefix beam search가 $p_b$ 와 $p_{nb}$ 를 따로 두는 이유는 무엇인가요? (답: 다음 프레임에 같은 글자가 왔을 때 글자가 늘어나는지 이어지는지가 마지막 프레임이 blank였는지에 달려 있습니다)
3. $\beta$ 항이 없으면 언어 모델을 붙인 디코더는 어느 방향으로 치우치나요? (답: 짧은 문장. $\log P_{lm}$ 이 글자마다 음수를 더합니다)
4. 위 측정에서 beam 16과 beam 500의 CER이 같은데 계산량은 30배입니다. 남은 오류를 beam 폭으로 고칠 수 없는 이유는 무엇인가요? (답: 정답 문장이 후보에 들어 있는데도 점수가 낮습니다. 탐색 실패가 아니라 점수 함수의 순위 문제입니다)
5. 언어 모델 없이 beam 폭을 키웠을 때 CER이 나빠진 것을 어떻게 읽어야 하나요? (답: 탐색이 잘 된 결과입니다. $\log P_{ctc}$ 가 더 큰 문자열을 찾았고 그것이 정답이 아닙니다)
6. 프레임별 가지치기 임계값을 $5 \times 10^{-2}$ 까지 올려도 CER이 그대로인데, 이 값을 실제 시스템에 그대로 쓰면 어떤 위험이 있나요? (답: 정답 글자의 확률이 그보다 낮은 프레임이 있으면 그 글자가 후보에서 사라집니다. 이 합성 설정에 그런 프레임이 없었을 뿐입니다)
