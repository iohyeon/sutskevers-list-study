# 발화를 길이순으로 정렬해 배치를 만들면 무엇이 좋아지는가?

## 문제

길이가 다른 시퀀스를 한 배치에 넣으려면 짧은 것을 가장 긴 것의 길이까지 패딩해야 합니다. 어떤 발화를 같은 배치에 넣을지는 자유롭게 정할 수 있고, 무작위로 묶는 것과 길이가 비슷한 것끼리 묶는 것 사이에 두 가지 차이가 생깁니다. 하나는 계산량입니다. 패딩 칸도 행렬 곱을 지나므로 배치 안의 길이 차이가 크면 버리는 계산이 많아집니다. 다른 하나는 학습 초기의 안정성입니다. 발화 하나에 loss 하나가 붙는 목적 함수에서는 긴 발화의 loss와 기울기가 짧은 발화보다 큽니다.

Deep Speech 2는 첫 epoch에서만 발화를 길이순으로 정렬해 미니배치를 돌리고 이후 epoch에서는 섞는 방식을 썼고 SortaGrad라고 불렀습니다. 패딩 비율을 계산과 실측으로 재고, 길이가 loss와 기울기 크기를 어떻게 바꾸는지 재고, 정렬 방식을 셋으로 나눠 비교합니다.

## 아이디어

패딩 비율은 배치 구성만으로 정해지는 양입니다. 배치 안의 길이가 고르면 0에 가까워지고, 길이가 제각각이면 절반을 넘습니다. 길이순 정렬은 이것을 데이터 분포와 상관없이 낮춥니다.

학습 초기의 안정성은 목적 함수의 정의에 걸립니다. CTC는 발화 하나에 대해 $-\ln p(\mathbf{y} \mid \mathbf{x})$ 를 계산하므로 출력 글자 수가 늘면 loss가 함께 커집니다. 프레임 수로 나눠 평균을 내지 않는 한 긴 발화가 큰 기울기를 만들고, 초기 파라미터에서는 그 기울기가 제대로 된 방향을 가리키지도 않습니다. 짧은 발화부터 넣으면 첫 갱신들이 작아지고, 모델이 어느 정도 맞추게 된 뒤에 긴 발화를 만나게 됩니다.

첫 epoch만 정렬하는 이유는 길이순 정렬이 배치 사이의 순서를 고정하기 때문입니다. 정렬을 계속 유지하면 매 epoch 같은 발화들이 같은 배치에 묶이고 짧은 발화에서 긴 발화로 가는 같은 순서를 반복합니다. SortaGrad는 첫 epoch에서만 그 순서를 쓰고 그 뒤로는 섞습니다.

## 수식으로 보기

### 패딩 비율

배치 하나에 발화 $B$ 개가 있고 길이가 $L_1, \dots, L_B$ 라면 패딩까지 채운 칸 수는 $B \cdot \max_i L_i$ 이고 실제 프레임 수는 $\sum_i L_i$ 입니다. 데이터 전체에 대한 패딩 비율은 배치별 비율의 평균이 아니라 총합의 비율로 정의합니다.

$$
p = 1 - \frac{\sum_{b} \sum_{i \in b} L_i}{\sum_{b} B \cdot \max_{i \in b} L_i}
$$

길이가 구간 $[0, 1]$ 의 균등분포에서 독립으로 나온다고 두면 두 경우를 닫힌 식으로 쓸 수 있습니다.

**무작위 순서.** 한 배치의 길이는 균등분포에서 뽑은 $B$ 개이므로 평균의 기댓값이 $1/2$ 이고, 최댓값의 기댓값은 균등분포의 최대 순서통계량 공식에서 $B/(B+1)$ 입니다.

$$
p_{\text{random}} = 1 - \frac{1/2}{B/(B+1)} = 1 - \frac{B+1}{2B} = \frac{B-1}{2B}
$$

$B$ 가 커지면 $1/2$ 로 올라갑니다. 배치가 클수록 그 안에 아주 긴 발화가 하나 들어갈 확률이 높아지고, 그 하나가 배치 전체의 칸 수를 정합니다.

**길이순 정렬.** 발화 $N$ 개를 정렬한 뒤 앞에서부터 $B$ 개씩 끊으면 배치가 $G = N/B$ 개 생깁니다. 균등분포의 순서통계량은 $\mathbb{E}[L_{(k)}] = k/(N+1)$ 이므로 $g$ 번째 배치의 최댓값은 순위 $gB$ 짜리이고 기댓값이 $gB/(N+1)$ 입니다.

$$
\sum_{g=1}^{G} B \cdot \frac{gB}{N+1} = \frac{B^2}{N+1} \cdot \frac{G(G+1)}{2}, \qquad
\mathbb{E}\Big[\sum_i L_i\Big] = \frac{N}{2}
$$

$$
p_{\text{sorted}} = 1 - \frac{N/2}{\dfrac{B^2 G(G+1)}{2(N+1)}} = 1 - \frac{N(N+1)}{B^2 G (G+1)} = 1 - \frac{BG+1}{B(G+1)} \;\approx\; \frac{1}{G+1} = \frac{B}{N+B}
$$

두 식의 성질이 반대입니다. 무작위 순서의 패딩 비율은 배치 크기에만 걸리고 데이터가 많아져도 줄지 않습니다. 길이순 정렬의 패딩 비율은 배치 수 $G$ 에 걸리므로 데이터가 많아지면 함께 줄어듭니다.

### 길이에 따른 loss와 기울기 크기

출력이 $K$ 가지인 프레임 분류에서 초기 파라미터의 출력 확률은 거의 균등하므로 프레임 하나의 loss가 $\ln K$ 근처입니다. 목적 함수를 두 가지로 쓸 수 있습니다.

$$
L_{\text{utt}} = \frac{1}{B}\sum_{i=1}^{B} \sum_{t=1}^{T_i} \ell_{i,t} \;\approx\; \bar{T} \ln K,
\qquad
L_{\text{frame}} = \frac{\sum_i \sum_t \ell_{i,t}}{\sum_i T_i} \;\approx\; \ln K
$$

발화당 합인 $L_{\text{utt}}$ 는 길이에 비례하고 프레임당 평균인 $L_{\text{frame}}$ 은 길이와 무관합니다. CTC의 loss는 앞쪽에 해당합니다.

기울기는 시점별 기여의 합입니다.

$$
\nabla_\theta L_{\text{utt}} = \frac{1}{B}\sum_{i}\sum_{t} \nabla_\theta \ell_{i,t}
$$

$T$ 개 항의 합이므로 노름이 어떻게 자라는지는 항들의 방향에 걸립니다. 항들이 서로 독립이고 평균이 0이면 노름이 $\sqrt{T}$ 로 자라고, 항들이 같은 방향을 가리키면 $T$ 로 자랍니다. 초기 파라미터에서는 모든 시점이 같은 출력 layer와 같은 bias를 지나므로 후자에 가깝습니다. 실측으로 확인합니다.

## 작은 숫자로 직접 계산

### 패딩

발화 4개의 길이가 60, 45, 30, 22 입니다. 실제 프레임 수는 157입니다.

배치 하나에 4개를 모두 넣으면 칸 수가 $4 \times 60 = 240$ 이고 패딩 비율이 $1 - 157/240 = 0.3458$ 입니다.

길이순으로 정렬해 2개씩 끊으면 배치가 $(22, 30)$ 과 $(45, 60)$ 입니다. 칸 수가 $2 \times 30 + 2 \times 60 = 180$ 이고 패딩 비율이 $1 - 157/180 = 0.1278$ 입니다. 같은 발화 4개인데 비율이 0.35에서 0.13으로 내려갑니다.

무작위로 2개씩 끊으면 짝이 어떻게 걸리는지에 따라 달라집니다. $(60, 22)$ 와 $(45, 30)$ 이면 칸 수가 $120 + 90 = 210$ 이고 비율이 0.2524 입니다.

### 균등분포 식의 값

$B = 32$ 를 위 식에 넣습니다.

$$
p_{\text{random}} = \frac{32 - 1}{2 \times 32} = \frac{31}{64} = 0.4844
$$

발화 $N = 2048$ 개를 32개씩 끊으면 $G = 64$ 이므로 다음과 같습니다.

$$
p_{\text{sorted}} \approx \frac{1}{64 + 1} = \frac{1}{65} = 0.01538
$$

31.5배 차이입니다. 배치를 128로 키우면 $p_{\text{random}} = 127/256 = 0.4961$ 로 거의 그대로인데 $p_{\text{sorted}} = 1/17 = 0.0588$ 로 4배 가까이 나빠집니다. 배치가 커지면 정렬의 이점이 줄어듭니다.

### loss

상태가 8가지이므로 프레임 하나의 초기 loss가 $\ln 8 = 2.0794$ 입니다. 길이 80인 발화의 초기 loss는 발화당 합으로 쓰면 $80 \times 2.0794 = 166.4$ 이고, 길이 20인 발화는 $20 \times 2.0794 = 41.6$ 입니다. 같은 배치에 섞여 있으면 긴 쪽이 기울기의 4배를 내놓습니다.

## 코드로 확인

`experiments/sys_sortagrad.py` 가 세 가지를 잽니다. 패딩 비율은 정렬 여부만 바꿔 총합으로 계산합니다.

```python
def pad_ratio(lengths, batch, order):
    idx = np.argsort(lengths, kind="stable") if order == "sorted" else np.arange(len(lengths))
    real = alloc = 0
    for s in range(0, len(lengths) - len(lengths) % batch, batch):
        chunk = lengths[idx[s:s + batch]]
        real += int(chunk.sum())
        alloc += int(chunk.max()) * batch
    return 1.0 - real / alloc
```

배치 구성은 `mode` 로 갈립니다. `sortagrad` 는 첫 epoch에만 정렬합니다.

```python
def batches(lengths, n, batch, mode, epoch, rng):
    idx = np.arange(n)
    if mode == "sorted" or (mode == "sortagrad" and epoch == 0):
        idx = idx[np.argsort(lengths[idx], kind="stable")]
    else:
        rng.shuffle(idx)
    return [idx[s:s + batch] for s in range(0, n - n % batch, batch)]
```

학습에는 발화당 loss 합을 씁니다. 길이 효과를 보려는 것이므로 프레임 수로 나누지 않습니다. 평가와 보고는 프레임당 loss로 합니다.

```python
def per_utt_loss(logits, y, mask):
    ll = cross_entropy(...).reshape(y.shape)
    return (ll * mask).sum() / y.shape[0]        # 발화 수로만 나눈다
```

gradient clipping은 쓰지 않았습니다. clipping을 걸면 길이에서 오는 기울기 크기 차이가 가려집니다. 대신 매 스텝 기울기 노름을 기록하고, 노름이 $10^3$ 을 넘은 스텝 수를 셉니다.

모델은 layer 2개, hidden 64인 단방향 tanh 순환 모델이고 과제는 [08-sequence-wise-batchnorm.md](08-sequence-wise-batchnorm.md) 와 같은 합성 프레임 분류입니다. 발화 길이는 중앙값 45프레임인 로그정규를 $[20, 120]$ 으로 자른 것입니다.

## 결과 해석

패딩 쪽 결과는 계산과 실측이 맞았습니다. 무작위 순서의 패딩 비율은 배치 크기로 정해지고 $B$ 가 커지면 0.5로 올라갑니다. 길이 분포의 폭이 넓어지면 그 상한도 함께 올라가서, 중앙값 500프레임의 로그정규에서는 배치 64에서 0.8326까지 갔습니다. 길이순 정렬의 패딩 비율은 배치 수에 반비례하므로 데이터가 많을수록 유리합니다. 이 이점은 학습 결과와 무관하게 확보되는 것이고, 정렬을 채택할 근거로는 이쪽이 더 단단합니다.

초기 안정성 쪽은 목적 함수의 정의에서 나옵니다. 발화당 loss 합을 쓰면 기울기 노름이 길이에 거의 정비례($T^{0.97}$)합니다. 배치를 섞으면 배치의 기울기 크기가 그 배치에 어떤 길이가 들어왔는지에 따라 스텝마다 달라지고, 고정 학습률에서는 그 변동이 그대로 갱신 크기의 변동이 됩니다. 학습률 0.05에서 섞은 순서는 seed 8개 전부에서 기울기 노름이 $10^3$ 을 넘는 스텝을 만들었고, 한 번 튀면 파라미터가 망가져 loss가 회복되지 않았습니다. 길이순으로 넣으면 첫 스텝들이 가장 짧은 발화로 시작하므로 갱신이 작고, 모델이 어느 정도 맞추게 된 뒤에 긴 발화를 만나 그때는 프레임당 loss가 이미 내려가 있습니다. 8개 seed 전부에서 노름이 $10^3$ 을 넘은 스텝이 0이라는 것은 이 순서가 초기 폭주를 막았다는 뜻입니다.

학습률을 0.01로 낮추면 세 방식의 차이가 거의 사라집니다. 마지막 val frame error가 0.2192, 0.2238, 0.2256 이고 seed 표준편차가 0.0029에서 0.0077 입니다. 차이가 표준편차의 한 배 안팎이므로 이 규모에서는 순위를 말할 수 없습니다. 안전한 학습률을 고르면 배치 구성이 최종 성능을 바꾸지 않았다고 읽는 것이 맞습니다. 정렬의 값은 최종 성능이 아니라 폭주 없이 쓸 수 있는 학습률의 범위를 넓히는 것에 있습니다.

## 한계와 주의할 점

첫 epoch만 정렬하는 것이 계속 정렬하는 것보다 낫다는 결과는 나오지 않았습니다. 학습률 0.01, 4 epoch에서 계속 정렬한 쪽의 마지막 val frame error가 0.2192로 가장 낮았고 첫 epoch만 정렬한 쪽이 0.2256으로 가장 높았습니다. 차이가 seed 표준편차 안이므로 어느 쪽이 낫다고 말할 수 없는 상태입니다. 논문이 첫 epoch 뒤에 섞는 이유는 이 실험으로 확인되지 않았고, 이 규모와 4 epoch이라는 짧은 학습에서는 같은 배치 구성을 반복하는 부작용이 드러날 만큼 epoch 수가 많지 않습니다.

과제가 논문과 다릅니다. 논문은 CTC로 글자열을 맞추고 평가 지표가 WER입니다. 여기서는 프레임마다 정답이 있는 분류이고 지표가 frame error rate입니다. CTC에서는 발화가 길어질 때 정렬 후보의 수가 함께 늘어나므로 긴 발화의 어려움이 여기보다 큽니다.

길이 분포도 다릅니다. 학습에 쓴 분포는 $[20, 120]$ 으로 자른 것이라 최대와 최소의 비가 6배입니다. 음성 말뭉치는 1초짜리와 30초짜리가 섞이므로 비가 더 큽니다. 패딩 측정의 (c) 항목이 그 범위에 가깝고, 학습 실험은 (b) 항목의 좁은 분포에서만 돌렸습니다.

기울기 노름의 로그-로그 기울기 0.972는 초기 파라미터에서만 잰 값입니다. 학습이 진행되면 시점별 기울기의 방향이 흩어지므로 이 지수가 유지되지 않습니다.

패딩 비율은 버리는 계산의 비율이고 실제 시간 절감과 같지 않습니다. 길이가 비슷한 발화끼리 묶으면 배치마다 텐서 모양이 달라져 커널 재컴파일이나 메모리 재할당이 생길 수 있고, 마스크 처리 비용도 듭니다. 이 문서에서 실행 시간을 직접 비교하지 않았습니다.

학습률 0.05에서의 폭주는 clipping을 끄고 본 것입니다. `clip_grad_norm_` 을 걸면 튀는 스텝이 잘려서 섞은 순서도 학습이 진행됩니다. 실제 시스템은 clipping을 함께 쓰므로, 정렬이 없으면 학습이 불가능하다는 뜻으로 읽으면 안 됩니다.
